# tools/art – procedural oil-pastel illustrations

Everything under `public/assets/avatars/`, `public/assets/art/` and `public/assets/textures/`
is generated by this folder. Output is deterministic (seeded mulberry32, no `Math.random`):
two runs produce byte-identical files.

```sh
npm run art                                 # = build.mjs && soften.mjs (the full pipeline)
node tools/art/build.mjs                    # all avatars, art/ and the three texture tiles
node tools/art/soften.mjs                   # derives grain-soft.png / crayon-light-soft.png (alpha ×0.3 / ×0.6)
                                            # from the tiles – the app uses these as CSS background layers
node tools/art/build.mjs --only=lime,crown  # just some assets (ids / file names)
node tools/art/build.mjs --no-textures      # skip the PNG tiles
node tools/art/preview.mjs                  # tmp/art-preview/contact.html + .png (needs Google Chrome for the PNG)
node tools/art/preview.mjs --one=lime,sol   # big single views;  --art  illustrations;  --tex  3×3/2×2 seam check
```

## Layout

| file | what |
| --- | --- |
| `lib/rng.mjs` | seeded PRNG (`new Rng('seed').fork('part')` gives independent sub-streams) |
| `lib/path.mjs` | compact path writer: quantised relative commands, Catmull-Rom → Bézier |
| `lib/geom.mjs` | points, blobs (`blobPoints`), tubes (`tubePoints`), sampling |
| `lib/shape.mjs` | `Shape`: union of smooth parts → outline path, inside test, exterior boundary with tangents |
| `lib/pastel.mjs` | the stroke vocabulary: `hatch` (flow-field strokes), `rim`, `scratches` (white highlights), `render` (batching), `paint` (one shape, start to finish) |
| `lib/recipes.mjs` | `pastelSpec(palette)` – the shared layering recipe every body uses |
| `lib/eye.mjs` | the giant eye (socket, sclera, iris, pupil, lids, lashes, tear, brow, slit/spiral pupils) |
| `lib/parts.mjs` | leaf, stem/tube, blueberry crown, lips, curls, sparkle shape |
| `lib/svg.mjs` | `Canvas` (id-prefixed defs) + the paper filter |
| `characters/*.mjs` | one module per avatar (ids match `shared/avatars.mjs`) |
| `art/eyes.mjs`, `art/decor.mjs` | role/reveal eyes and decorative bits |
| `textures.mjs` | seamless PNG tiles (JS rasteriser + sharp, 16-colour palettes) |
| `soften.mjs` | post-step (app-owned): alpha-reduced copies of two tiles for CSS layers – keep it |

## Technique

* **Fill** = flat base + 5–8 hatch passes (mid, shadow, deep, neighbour hue, light, pale, warm) of short
  curved round-capped strokes. Stroke direction comes from an orientation field: a dominant diagonal
  inside, bending to follow the outline near the edge and swirling around "guide" shapes (eye sockets).
  Tone (0 rim … 1 lit centre) picks which pass a stroke belongs to, with jitter so layers interleave.
* **Rim**: 2–3 offset passes of strokes hugging the outline (darker, saturated).
* **Highlights**: cream dashes + dots on the lit (upper-left) side, following the contour.
* **Paper filter** (one per file, 3 turbulences): low-frequency displacement (hand wobble), fine
  displacement (ragged waxy stroke edges), and patchy cream specks (paper tooth). Specks are tinted
  instead of punched out so they read the same on the yellow tiles and on burgundy (the scribbles do
  punch real holes).
* Strokes are batched into a few `<path>`s per (colour, width, opacity) – split in 2 so overlaps
  still build up. Hatch strokes use integer coordinates, details 0.1.

## Compatibility rules (keep them)

Must render the same via `<img>` in Chrome and iOS Safari: no external refs, fonts, `<image>`,
`<foreignObject>`, CSS blend modes or animation; every `id` is prefixed with the asset id;
at most 2 filters per file with an explicit `userSpaceOnUse` region. Avatars stay inside a circle of
r≈186 around the centre (safe in round tiles). Budget: ≤45 KB per avatar (80 KB hard cap – the build
fails above it).

## Adding an avatar

Copy `characters/lime.mjs`, change the seed/shape/palette/eye options, register it in
`characters/index.mjs`, run the build and `preview.mjs --one=<id>`.
